\chapter*{Streszczenie}
\addcontentsline{toc}{chapter}{Streszczenie}

Praca pt.\ \textit{„Architektura mikroserwisów i~rozwiązania chmurowe w~ekosystemie .NET”} poświęcona jest projektowaniu, implementacji oraz empirycznej analizie wydajności systemu rozproszonego zbudowanego w~oparciu o~platformę .NET~10. W~ostatnim czasie obserwuje się intensywny rozwój protokołu gRPC jako alternatywy dla powszechnie stosowanego REST w~komunikacji między mikroserwisami. Jednocześnie środowisko przeglądarek internetowych wymaga stosowania wariantu \textit{gRPC-Web}, którego wydajność w~komunikacji klient--backend pozostaje słabo zbadana empirycznie. W~rozważanej pracy podjęto zatem próbę wypełnienia tej luki badawczej. W~szczególności zebrano wiadomości z~zakresu architektury mikroserwisów, mechanizmów komunikacji synchronicznej i~asynchronicznej oraz wzorców projektowych w~ekosystemie .NET, porównano trzy warianty komunikacji klient--backend: REST (HTTP/JSON), gRPC-Web przez proxy Envoy oraz gRPC-Web Direct bez pośrednika, opracowano środowisko testowe oparte na~narzędziu k6 i~platformie Docker~Compose, zrealizowano aplikację referencyjną eShop złożoną z~dwóch mikroserwisów (\textit{ProductService} i~\textit{OrderService}) w~technologii ASP.NET Core~10, przetestowano wydajność poszczególnych protokołów przy różnych poziomach obciążenia (10, 50 i~100 wirtualnych użytkowników) i~rozmiarach ładunku (10--200 rekordów). Zaprojektowany i~zaimplementowany system charakteryzuje się następującymi cechami: podejściem \textit{contract-first} opartym na~\textit{Protocol Buffers} zapewniającym silną typizację w~całym stosie technologicznym, kompleksową obserwowalnością obejmującą metryki (Prometheus, Grafana) i~ślady rozproszone (Jaeger), implementacją wzorców klasy enterprise (Transactional Outbox, Saga State Machine). Dzięki temu zaprojektowany i~zaimplementowany system może być wykorzystany w~praktyce np.\ do:~porównywania wydajności protokołów komunikacyjnych w~architekturze mikroserwisowej .NET, demonstracji wzorców projektowych stosowanych w~systemach rozproszonych, a~także jako platforma testowa dla nowych scenariuszy komunikacji sieciowej.

Do~realizacji praktycznej części pracy wykorzystano najnowsze narzędzia i~technologie informatyczne, w~tym m.in.\ \textit{.NET~10} i~\textit{ASP.NET Core Minimal API}, framework gRPC z~serializacją \textit{Protocol Buffers}, framework frontendowy \textit{Angular~20} z~biblioteką \textit{Connect RPC}.

Zaprojektowany i~zaimplementowany system można w~przyszłości przykładowo rozbudować o~następujące funkcje: wdrożenie w~środowisku Kubernetes (Azure AKS) z~automatycznym skalowaniem horyzontalnym, dodanie warstwy uwierzytelniania JWT i~autoryzacji na~poziomie serwisów oraz rozszerzenie macierzy testowej o~scenariusze mutacji danych i~testów odporności (chaos engineering).

\chapter*{Summary}
\addcontentsline{toc}{chapter}{Summary}

This thesis, entitled \textit{``Microservices Architecture and Cloud Solutions in the .NET Ecosystem''}, is devoted to the design, implementation, and performance analysis of a~distributed system built on the .NET~10 platform. With the growing adoption of the gRPC protocol in backend communication, its browser-compatible variant \textit{gRPC-Web} has emerged as a~significant yet underexplored alternative to the ubiquitous REST protocol for client-backend communication. This work addresses that research gap. In~particular, knowledge was gathered in the areas of microservices architecture, synchronous and asynchronous communication mechanisms, and design patterns used in the .NET ecosystem; three client-backend communication variants were compared: REST (HTTP/JSON), gRPC-Web via Envoy proxy, and gRPC-Web Direct without a~proxy; a~testing environment was built using the k6 load testing framework on Docker Compose; a~reference eShop application consisting of two microservices (\textit{ProductService} and \textit{OrderService}) was implemented in ASP.NET Core~10; and the performance of each protocol was measured at different load levels (10, 50, and 100 virtual users) and payload sizes (10--200 records). The designed and implemented system is characterised by: a~contract-first approach based on \textit{Protocol Buffers} ensuring strong typing across the entire technology stack, comprehensive observability including metrics (Prometheus, Grafana) and distributed tracing (Jaeger), and implementation of enterprise patterns (Transactional Outbox, Saga State Machine). The system can be used in practice for comparing the performance of communication protocols in a~.NET microservices architecture, demonstrating design patterns in distributed systems, and serving as a~testing platform for new network communication scenarios. Future extensions may include deployment to a~Kubernetes environment (Azure AKS) with horizontal autoscaling, addition of JWT authentication and service-level authorisation, and expansion of the test matrix to cover mutation scenarios and resilience testing.
